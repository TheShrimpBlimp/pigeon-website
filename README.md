# PIGEON download and setup site

These source templates target the **PIGEON 0.5 candidate**, with 500 KiB usable
shared sample storage. THE FINAL BETA publishes the 0.5 candidate after maintainer-reported hardware acceptance. Screen-reader support is included in the standard firmware. Published assets are under `dist/client/`; generated from the current firmware and web sources. The Pages workflow deploys that directory.

Edit `index.html` and `site.css` here. The current offline sample tool stays in
`../pigeon/`; firmware packaging lives in `../make_site.py`.

From the project root, build with:

```sh
.venv/bin/python web/make_site.py build/pigeon.fwsc 0.5-dev web/site/build/pages
```

The generated output contains the complete static site, current firmware, matching source,
licences, installer, guides, and browser sample tool. Imported user audio is not
included. The landing page uses local fonts and no external scripts.

Serve `build/pages/` with a loopback-only static server to preview locally. For USB MIDI,
use desktop Chrome or Edge at localhost or on HTTPS. Firmware upload remains a
user-initiated action; visiting the site does not write to a device.

The Sites project identity is retained in `.openai/hosting.json`. Its initial
hosted audience is private. The main firmware Git checkout is separate from the
site's hosting checkout.

## Install counts

The hosted build includes a Worker API and a D1 database (`DB`).
`worker/index.js` serves `/api/installs`; other paths use the asset binding.
`drizzle/0000_installs.sql` is the schema migration. GET returns the total and
counts by firmware SHA-256. Each successful install gets a random event UUID;
retries with the same UUID count once, and reinstalls get new UUIDs.
No samples, MIDI data, device identity, account ID, or IP address are stored in
this database. Platform operational logs are separate. Reports are generated by
the browser, can be forged, and do not measure unique hardware. Earlier CLI
installs are not backfilled. Offline events retry when online; clearing browser
storage before delivery loses those reports. Statistics never block flashing.
The existing private Site audience continues to apply to this API and website.
Build output now uses `dist/client/` assets and `dist/server/` Worker code.

## Browser trial

The homepage links `webapp/emu/`, a WebAssembly build of PIGEON running against
an FM1 HAL. Build from the firmware checkout with `sh web/emu/build.sh`
(Emscripten required) before `web/make_site.py`. It starts empty. Users load their
own songs and up to 16 drum samples. Each file has waveform selection, start/end
trim fields, zoom, scroll, loop preview and explicit Apply controls. Full sources
and applied trim ranges persist for editing again after reload. Imports are normalized, downmixed and
resampled locally to 22.05 kHz. FM1 mode offers per-song MP3 compression at
24, 32, 40, 48, 56 or 64 kbps (64 by default), using the sample tool’s bundled
encoder. Drum pads use IMA ADPCM. Unlimited mode uses IMA ADPCM for songs. FM1 storage mode enforces the real
496 KiB shared payload pool, including waveform/alignment overhead. Unlimited
mode uses a browser-only expanded bank and is bounded by browser memory, rather
than FM1 flash. Samples persist in IndexedDB, virtual settings/projects in
separate browser-local flash. No samples are uploaded or included in releases.

Connect a MIDI controller (including the FM1) requests ordinary Web MIDI input
only, without SysEx permission, output messages or firmware changes. Controller
keys play the selected browser track. Editing uses the on-screen panel.
The page uses lit.chr and the main site palette. Its credits link directly to
Charles Vestal's FM1 X0X emulator wrapper, AudioWorklet and interactive panel,
and credit the Felucca adaptation by Leo Kuroshita and Hügelton Instruments.

## Anonymous trial counter

The emulator's shared nixie counter records a successful browser start once per
random browser ID in local storage. Reopening/retrying uses the same ID. Clearing
site data or using another browser creates another trial; this does not measure
unique people. Only the random ID and day are stored; no audio, device identity,
account or IP is written to the database. GET/POST `/api/trials` is shared by the
hosted Worker and public counter. Apply `drizzle/0001_trials.sql` before deploying.
